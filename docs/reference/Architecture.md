# Architecture Map

Before starting an agent's local listener or game session, `src/main.py` uses `src/net/rest/KmPlayer` to query its account-and-character KM identity and create a missing `Som-Agentic-Player`. Every runtime startup reuses the same situation; failures stop startup. Player-scoped REST calls retain assertions across runtime sessions while som-nlp-service remains running. See [Play](Play.md) for identity encoding and the service's in-memory persistence limit.

- `src/main.py` loads `resources/agent.yml`, writes INFO logs to `log/agent.log` under the repository root, reads agents with `GET /api/v1/agents`, and listens on the local control socket. The agent starts idle. The first `play` bootstraps game knowledge. A later login restores learned command descriptions and verifies available verbs from one fresh game `commands` response before play. `bootstrap` runs that login again. When `bootstrap.initial` is true, startup connects the saved account for the agent's `accountName`, logs on `characterName`, and runs that same bootstrap before the control loop. The mode stays idle. While the mode is `play`, the drive thread repeats the observe-decide-act step in [Play](Play.md).
- `src/agent` owns `Agent`, `AgentCollection`, `AgentRegistry`, and `AgentConfig`.
- `src/control` owns `PlayerControl` and `GameplayOutput`. `handle` accepts `idle`, `play`, `bootstrap`, `memory`, `output`, `connect`, `list`, and `logon`. `drive` calls the play setup once, then calls `GameplayEngine.step` while the mode stays `play`.
- `src/cli` is the operator invoker. `python -m cli` sends one known command. `src/net/local/ControlServer` accepts it on `127.0.0.1`. The transport is one raw TCP socket.
- `src/net/AccountSession` connects a saved account and logs on with one character from that login.
- `src/play` owns the first-login `Bootstrapper`, `CommandChannel`, help and world readers, `WorldKnowledge`, `MemoryObservation` parsers, the shared `ObservationPipeline`, `BootstrapCompletion`, and `GameplayEngine`. Bootstrap, restoration, and gameplay fold replies through that pipeline; `absorb_world` remains a legacy compatibility helper rather than the runtime bootstrap path. The engine asks one level question through `KmClient` when `resources/agent.yml` has a `goal` section.
- `src/memory` owns short-lived `WorkingMemory` for the current session: players, agentic players, mobiles, NPCs, rooms, commands, `ConsiderOpponent` records, conversations, and aggressive mobiles. It also owns `PlaySession`, composed of `PlayClock` progress, `RoomVisit`, `CombatState`, and an optional `PendingAction`. `SessionBeing`, `SessionRoom`, `SessionItem`, and `RoomExit` hold ID-addressable provisional sightings and directed map evidence. Current presence references these IDs; accumulated lists remain history. The engine reads this memory-owned state; operator review includes it, while the legacy memory REST body omits it. KnownCommand and CommandList provide shared command values/rules. WorldKnowledge owns descriptions; a compatibility memory view shares that collection during bootstrap/restoration. PlaySession owns observed availability independently. The other sections are not part of that document.
- `src/prompt` fills a prompt's tokens before that text is submitted to som-nlp-service. A caller that needs a prompt loads it with `GET /api/v1/agent-prompts/{name}`.
- `src/net/rest` retrieves the auth token, loads agents and prompts, loads and saves working memory, loads and saves world knowledge, calls the Ollama service, and calls Knowledge Machine. The modulith origin is `api.base_url`. `AuthClient` posts to `/api/auth/login` and stores the `Authorization` response header, matching `springs-of-mud-ui`. `AgentClient` gets `/api/v1/agents`. `PromptClient` gets `/api/v1/agent-prompts`. `MemoryClient` gets and puts `/api/v1/agent-memory/{agentName}`. `KnowledgeClient` gets and puts `/api/v1/agent-knowledge/{characterId}`. `OllamaClient` posts to `/ollama/completions`. `KmClient` posts to som-nlp-service `/km/query`, `/km/assertions`, and `/km/baseline`. The play step uses `/km/baseline`.
- `src/net/telnet` owns the telnet socket client and `PlayerSession`, which sends the server `logon` line.
- `src/util` holds small shared helpers: camelCase conversion and reading or writing a JSON collection file.
- `resources/agent.yml` holds the auth URL, telnet host and port, `api.base_url`, the local control address, and the collection location.
- `resources/collections/SOMDB.Agents.json` is the unit-test fixture for `SOMDB.Agents`. `SOMDB.Prompts.json` is the unit-test fixture for prompts. `SOMDB.Memories.json` is the local working-memory fixture, one document per agent.

`src/memory` also owns SessionEvidence, EvidenceJournal, and BootstrapProgress. The queue and completion requirements appear in live review and stay outside the legacy REST documents. Local collection, KM acceptance, and durable saving are separate boundaries; typed mapping plans are provided by KmEvidenceAdapter, while periodic submission/acknowledgment follows in step 7. See [Evidence to Knowledge Machine](KmEvidence.md) for contracts and unsupported records.
